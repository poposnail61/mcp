# 노크플레이스 (Knockplace) 프로덕트 컨텍스트

## 서비스 개요
- **노크타운**: 폐쇄형 아파트 앱. 현재 유저 유입의 95% 담당. 기존 앱.
- **노크플레이스**: 동네 기반 하이퍼로컬 서비스. 단독 앱으로 확장 중.

## 핵심 전략 목표
1. 노크타운 유저를 노크플레이스로 락인(Lock-in) 및 전이
2. 노크타운 의존도를 낮추고 노크플레이스 단독 오가닉 유입 확대
3. 사장님-고객 연결 지도 + 스레드형 로컬 SNS 고도화

## 핵심 기능
- **사장님-고객 연결 지도**: 하이퍼로컬 지도 기반 매장 탐색. 로컬 API 연동, 복잡한 핀 렌더링 이슈 존재.
- **스레드형 로컬 SNS**: 동네 기반 커뮤니티. 무한 스크롤, 바이럴 루프 설계 중.

## 주요 지표
- MAU, 리텐션, CVR (노크타운→노크플레이스 전환율)
- 사장님 활성도 (지도 핀 업데이트 빈도, 스레드 참여율)
- 단독 앱 오가닉 유입 비율

## 유저 구분
- **폐쇄형 유저**: 아파트 인증 완료. 노크타운 경유.
- **일반 유저**: 동네 기반. 노크플레이스 직접 유입.
- **사장님 유저**: 매장 등록 및 홍보 주체.

## 기술 스택 맥락
- 웹뷰 + 네이티브 앱 브릿지 구조
- 노크타운 ↔ 노크플레이스 유저 DB 동기화 필요
- 위치 기반 하이퍼로컬 데이터 처리

## 토론 규칙 (모든 에이전트 공통)
- **1~3라운드**: 절대 타협 금지. 자기 관점을 극한까지 방어.
- **4라운드~**: 절충안 모색 시작.
- **최종 라운드**: MVP 합의안 도출.
- 형식적 인사말 없이 실무 용어로 직관적으로 논박할 것.
