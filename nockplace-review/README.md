# nockplace-review

노크플레이스 프로덕트 위원회 멀티에이전트 기획 리뷰 시스템.

PO와 PD가 안건을 두고 치열하게 논박하고, 필요에 따라 FE·BE·운영·마케팅·영업 자문을 소집해 최종 MVP 합의안을 도출한다.

---

## 컴포넌트

### 스킬

| 스킬 | 트리거 예시 |
|------|------------|
| `committee-review` | "안건 검토해줘", "기획 리뷰해줘", "위원회 시작해줘", "PO PD 토론해줘" |

### 에이전트

| 에이전트 | 역할 | 소집 조건 |
|---------|------|----------|
| `po` | PO — 비즈니스 임팩트·퍼널·지표 관점 | committee-review 스킬이 라운드마다 호출 |
| `pd` | PD — UX·사용성·인터페이스 완결성 관점 | committee-review 스킬이 라운드마다 호출 |
| `fe` | FE 자문 — 구현 가능성·웹뷰-네이티브 브릿지·퍼포먼스 | 기술 구현 이슈 시 |
| `be` | BE 자문 — 서버·DB·위치 데이터 처리 | DB/서버 아키텍처 이슈 시 |
| `ops` | 운영 자문 — CS·어뷰징·운영 정책 | 운영 리스크 이슈 시 |
| `marketing` | 마케팅 자문 — 바이럴·UA·훅 설계 | 오가닉 유입·확산 이슈 시 |
| `sales` | 영업 자문 — BM·사장님 온보딩 | 수익화·사장님 온보딩 이슈 시 |

### 훅

| 훅 | 동작 |
|----|------|
| `SessionStart` | 노크플레이스 도메인 컨텍스트(CLAUDE.md)를 세션 시작 시 자동 주입 |

## 사용법

### 기본 위원회 시작

```
"사장님 지도 핀 탭 → 스레드 연결 기능 안건 검토해줘"
"신규 유저 온보딩 플로우 개선 기획 리뷰해줘"
"로컬 SNS 스레드 바이럴 루프 피처 위원회 시작해줘"
```

### 특정 자문 소집

```
"FE 자문 불러줘, 지도 핀 클러스터링 구현 가능성 봐야 해"
"BE 자문, 유저 DB 동기화 이슈 리스크 확인해줘"
"운영 자문, 어뷰징 리스크 점검해줘"
"마케팅 자문, 바이럴 가능성 평가해줘"
"영업 자문, 사장님 BM 가능성 봐줘"
```

---

## 토론 구조

```
안건 수신 → 난이도 판단 (3~7라운드)
  └─ Step 1: PO vs PD 토론
       ├─ 1~3라운드: 타협 절대 금지, 각자 관점 극한 방어
       ├─ 4라운드~: 절충안 모색
       └─ 최종 라운드: MVP 합의안 도출
  └─ Step 2: 실무 자문 (필요시)
       ├─ 1R: 전문가 리스크·기회 지적
       ├─ 2R: PO/PD 수정안 또는 반박
       └─ 3R: 전문가 최종 승인 + 실무 주의사항
```
